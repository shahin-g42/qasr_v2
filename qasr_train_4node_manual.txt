================================================================================
 QASR 1.7B TRAINING — 4 NODE × 8 GPU MANUAL LAUNCH
================================================================================

 Master node: inception-H100-hpc-001  (change to your first node hostname)
 Nodes:       inception-H100-hpc-001, -002, -003, -004
 Port:        29500

 IMPORTANT:
   - Start ALL 4 nodes within the rdzv timeout (7200s = 2 hours)
   - Node 0 (master) MUST be started first or simultaneously
   - All nodes must see the same shared filesystem paths
   - Run `hostname` on each node to confirm the correct master_addr

================================================================================
 PHASE 1: PROJECTOR TRAINING (5,000 steps, ~3 hours)
================================================================================

--- [NODE 0] Master --- screen -S qasr-node0

conda deactivate
conda activate /lustrefs/shared/shahin.konadath/workspace/conda/envs/qasr
cd /lustrefs/shared/shahin.konadath/workspace/train/qasr
clear

pkill -9 python3
export CUDA_VISIBLE_DEVICES=0,1,2,3,4,5,6,7
export HF_HOME=/lustrefs/shared/shahin.konadath/workspace/train/qasr/.cache
export PYTHONPATH=$(pwd)/src
export TOKENIZERS_PARALLELISM=false
export OMP_NUM_THREADS=1
export NCCL_DEBUG=WARN
export NCCL_IB_DISABLE=0
export NCCL_NET_GDR_LEVEL=2

torchrun \
  --nnodes=4 \
  --nproc_per_node=8 \
  --node_rank=0 \
  --master_addr="inception-H100-hpc-001" \
  --master_port=29500 \
  --rdzv_backend=static \
  --rdzv_endpoint="inception-H100-hpc-001:29500" \
  --rdzv_conf=timeout=7200 \
  train.py --config configs/train_projector_4node.yaml

================================================================================
 TROUBLESHOOTING
================================================================================

 Problem: "Connection refused" or rendezvous timeout
 Fix:     Ensure master node (node 0) is started first.
          Check: nc -zv inception-H100-hpc-001 29500

 Problem: "NCCL WARN Cuda failure"
 Fix:     export CUDA_VISIBLE_DEVICES=0,1,2,3,4,5,6,7
          Ensure no other python processes: pkill -9 python3

 Problem: One node hangs, others wait
 Fix:     Check IB links: ibstat
          Check FS access: ls /lustrefs/shared/
          Restart that node's torchrun

 Problem: OOM on some GPUs
 Fix:     Reduce per_device_train_batch_size in config (4 → 2)
          Or increase gradient_accumulation_steps (1 → 2)

 Problem: Loss = NaN
 Fix:     Corrupt audio in dataset. Run data validation first:
          python -m qasr.validate_data --config configs/train_full_4node.yaml \
            --output-dir filtered/ --workers 64
