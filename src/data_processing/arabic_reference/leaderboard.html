Startup, first request & output diagnostics

Request latency starts with an audio waveform already in memory and ends with the final decoded text, including preprocessing and synchronized GPU work. Each model runs alone on the same reserved GPU. Warm-up and first-request timings are separate. This is offline processing latency; network upload, server queues, file reads and streaming first-token latency are not measured.

Percentiles pool repeated requests on the fixed clips. RTF divides total successful request time by audio duration; lower is faster. Failed requests are counted separately, with latency summaries based on successful calls. Empty, refused and token-limited outputs stay in the timings and are flagged. Native decoding limits differ. Peak allocated memory includes resident model tensors but excludes GPU context and non-PyTorch allocations. GPU clocks are observed, not locked; CPU contention can still affect timings.

Mean batch time is average inference service time per measured batch call, including processor work inside the call and OOM retries. It excludes model loading, audio-file reads and queue waiting. Compute / transcript divides summed worker inference time by completed transcript count; it is amortized compute, not request latency.

Transcripts / sec is completed outputs divided by total attempt wall time, including startup. These timings describe the full source runs; accuracy filters do not change them. Different batch sizes, worker counts and decoding modes prevent a controlled speed ranking. Missing measurements remain unavailable.

03 / THE ENHANCED REFERENCE

Arabic, with its written richness

What ideal_text_draft brings to the comparison, and why it matters.

THE COLUMN WE SCORE

A richer rendering of the proposed words

The enhanced track uses ideal_text_draft: contextual spelling, readable punctuation, selective diacritics, and consistent writing conventions. The policy considers أ / إ / آ / ؤ / ئ, ي / ى and ة / ه in context. It aims to preserve dialect, code-switching, names, numbers, negation and spoken repetition.

These are editorial aims, not a guarantee for every clip. The drafts were produced from source references and QASR/GQASR candidates through text-only correction and documented repairs. Final ideal_text and verified_text remain separate, listening-reviewed fields.

REFERENCE SENSITIVITY

Hold the audio and predictions fixed

Paired original and enhanced scores show how the reference changes the result on exactly the same clips. A lower enhanced score reflects closer agreement with that reference; the model’s predictions have not improved.

TWO SCORING VIEWS

Read normalized and strict together

Normalization removes selected surface differences, including common hamza forms and diacritics. Strict WER/CER retains them, measuring whole-transcript agreement with the written style. It does not isolate punctuation or linguistic quality.

05 / EVALUATION WITH CONTEXT

Know what a score means

Better presentation and verified spoken content are separate questions.

A

Original references

The default ranking uses the source datasets’ original transcripts and the saved forced-Arabic model predictions. It preserves all original clips, including duplicate audio.

B

Enhanced drafts

Contextual spelling, punctuation, diacritics and dialect-aware editorial proposals are scored separately. QASR and GQASR informed these drafts, so this is an exploratory agreement comparison.

C

Listening & verification

A fluent transcript or lower WER cannot establish what was spoken. Final reviewed tracks require recorded listening attestations.

Scoring rules & interpretation +

WER is word edit distance divided by reference word count. CER is character edit distance divided by reference character count, including spaces. Each dataset pools edit counts; the macro is the arithmetic mean of all six dataset rates. Error rates may exceed 100%.

Normalized applies the pinned ELM rules to both reference and prediction, including selected punctuation, diacritics, hamza, digit and conjunction normalization. Strict retains spelling, punctuation and diacritics, while normalizing whitespace. It measures whole-transcript agreement, not isolated punctuation quality.
